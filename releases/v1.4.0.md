Mod Enabled toggle added to every settings tab, ore sell prices now take effect immediately, and auto-collect passive batching overhauled to fix lag and physics/camera stutter.

## Changes

### der_floh-effect_spread_mod (1.0.3 → 1.1.0), der_floh-game_limits_mod (1.1.3 → 1.2.0), der_floh-passive_drop_mod (2.2.4 → 2.3.3), der_floh-tick_upgrade_mod (1.2.10 → 1.3.2), der_floh-ore_value_mod (1.0.4 → 1.1.1)

#### Added

- **Mod Enabled** toggle at the top of every settings tab (default: on). Disabling skips all mod logic and falls through to vanilla, without needing to uninstall.

---

### der_floh-ore_value_mod (1.0.4 → 1.1.1)

#### Changed

- Multiplier changes and toggling Mod Enabled now take effect immediately via `Gvars.reset_resources()` — no need to start a new day for prices to update.

---

### der_floh-passive_drop_mod (2.2.4 → 2.3.3)

#### Fixed

- Auto-collect: when many tiles break at once, dropped passives are now queued and processed one per frame via `SceneTree.process_frame` (CONNECT_ONE_SHOT), eliminating the single-frame lag spike. The previous `call_deferred` chain drained the entire message queue in one batch when the scene tree wasn't paused.
- Auto-collect: ore gravity and camera no longer stutter during batch collection. Each passive's `pickupEffect` call was triggering tick_upgrade's chooser hook, which pauses the scene tree — happening once per frame over N frames caused sustained physics and camera freezes. Fixed via a `_suppress_chooser_pause` flag that passive_drop sets while flushing its queue.

---

### der_floh-tick_upgrade_mod (1.2.10 → 1.3.2)

#### Fixed

- Passive chooser no longer pauses the scene tree when passive_drop_mod's auto-collect queue is active. The hook reads `_suppress_chooser_pause` from passive_drop_mod at call time and skips `get_tree().paused = true`; normal human-interaction pausing when picking passives manually is unchanged.
